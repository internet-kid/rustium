# Rustium — заметки для Claude Code

Прототип браузера: Rust + CEF 156 (крейт `cef` от tauri-apps, `=156.4.0`).
Окно на CEF Views в Alloy-стиле. Сверху BrowserView с HTML-панелью
(`ui/toolbar.html`), под ним панель с BrowserView вкладок (видна только
активная). Подробности — в README.md.

Целевые ОС: **Linux и macOS**.

## Команды

```sh
cargo check --features cef/dox --all-targets   # быстро, без бинарников CEF
cargo clippy --features cef/dox --all-targets
cargo test  --features cef/dox --lib
node scripts/ui-test.js                        # панель в Chrome, нужен playwright

cargo run                                      # Linux: запуск браузера
cargo run --bin bundle && open target/bundle/rustium.app   # macOS
```

Ошибки JS панели печатаются в stderr с префиксом `[toolbar]`.
С `RUSTIUM_DEBUG_PORT=9222` к любому браузеру (и к панели) можно
подключиться через CDP: Playwright `chromium.connectOverCDP('http://127.0.0.1:9222')`.
Так удобно проверять интерфейс автоматически: делать скриншоты, нажимать
кнопки панели и читать `document.title` вкладок.

## Всплывающие окна

Меню «⋯» и список загрузок — отдельный BrowserView (`ui/popup.html`),
добавленный в окно как overlay (`src/shell/popup.rs`). Панель присылает
`showPopup` с прямоугольником кнопки, страница меряет себя и присылает
`popupSize`, Rust ставит overlay под кнопку и отдаёт ему фокус. Закрытие —
по Esc, потере фокуса (`blur`) или любому другому действию (`Shell::perform`).
Браузер в CEF Views не бывает прозрачным (при прозрачном
`background_color` CEF рисует `CefSettings.background_color`), поэтому слой
точно равен карточке, без полей под тень. На macOS overlay — дочернее
`NSWindow`: `mac::style_popup_window` делает его прозрачным, обрезает слой
скруглением и включает системную тень. На Linux углы прямые.
`RUSTIUM_DEBUG_POPUP=1` печатает, нашлось ли окно.
У popup та же защита, что у панели: метка `UI_MARKER`, своя единственная
разрешённая страница в `on_before_browse`.

## DevTools внутри окна

`src/shell/devtools.rs`, `src/devtools_bridge.rs`. Штатные DevTools CEF
встроить нельзя: CEF 156 создаёт их только в Chrome-стиле, Alloy-окно такие
BrowserView не принимает (падение в `show_dev_tools`), а окно Chrome-стиля
ломается, когда его Chrome-браузер закрывается (падение при смене фокуса).
Поэтому встроенные DevTools — свой Alloy-BrowserView с фронтендом
`devtools://devtools/bundled/devtools_app.html?ws=…`, который через
WebSocket-мост (127.0.0.1, случайный порт, секретный токен в пути) говорит
со вкладкой по CDP: `send_dev_tools_message` / `add_dev_tools_message_observer`.
Отдельное окно — штатный `show_dev_tools`. Панель вкладок без layout-менеджера:
размеры считает `layout_content` (функция `split`), разделитель —
`ui/splitter.html`.

- Если `on_popup_browser_view_created` возвращает 1, view надо вставить в
  окно сразу, в самом колбэке (CEF зовёт его синхронно); отложенная вставка
  роняет процесс.
- События браузеров DevTools могут прийти с клиентом вкладки: роль
  определяет `Shell::role_of` по `identifier()` браузера.

## Правила кода

- **Не держать `Shell::state` заблокированным во время вызовов CEF.** CEF
  синхронно вызывает наши обработчики (например, `on_browser_created`
  внутри `add_child_view`, `do_close` внутри `close_browser`), и они снова
  берут блокировку, а `std::sync::Mutex` нереентерабелен. Схема везде одна:
  взять блокировку, скопировать нужное, отпустить и только потом звать CEF.
  Осторожно с `if let Some(x) = self.lock().field { ... }`: временный guard
  живёт до конца блока. Сначала присвойте значение переменной.
- Объекты CEF (BrowserView и т.п.) тоже нельзя отпускать (drop) под
  блокировкой: уничтожение view может синхронно закрыть браузер.
- Изменения дерева views из колбэков CEF откладывать через
  `task::post_ui(...)`.
- Макросы `wrap_*!` требуют **точных** сигнатур методов. Сигнатуры брать из
  привязок: `~/.cargo/registry/src/*/cef-156.4.0+156.0.26/src/bindings/<target>.rs`
  (`pub trait ImplXxx`). У `wrap_window_delegate!` и
  `wrap_browser_view_delegate!` обязательны все блоки `impl` (ViewDelegate,
  PanelDelegate, …), даже пустые, и структура с полями в фигурных скобках.
- Сигнатуры, зависящие от ОС (например, `on_pre_key_event` с нативным
  событием), объявляются отдельно под `#[cfg]` (см. `client.rs`).
- macOS-код (`src/mac.rs`, ветки `#[cfg(target_os = "macos")]`) на Linux
  не компилируется: проверять на Mac.
- `preferred_size`/`minimum_size` делегата view: обе стороны `Size` должны
  быть ненулевыми. Размер вроде `{width: 0, height: 80}` CEF считает пустым
  и молча игнорирует.
- Методы делегатов, которые не реализованы, в крейте `cef` возвращают 0,
  даже если в C++ CEF по умолчанию `true` (например, `can_maximize`).
  Нужное поведение задавать явно.
- `RustiumApplication` (mac.rs) должен отвечать на селекторы, которые
  Chromium шлёт в NSApp (например, `cancelTerminate:`), иначе падение
  с `unrecognized selector`.

## Что проверить при первом запуске

Код написан и проверен компилятором (Linux), тестами и UI-тестом панели.
Настоящий CEF в среде разработки не запускался, поэтому сначала пройти
по этим пунктам:

1. Окно открывается, панель высотой 80px сверху, новая вкладка занимает
   остальное место; фокус в адресной строке.
2. Ввод адреса или запроса и Enter — страница грузится, заголовок, favicon
   и полоса загрузки обновляются.
3. Закрытие вкладки (×, Ctrl/Cmd+W, средняя кнопка): вкладка исчезает,
   соседняя становится активной, в stderr нет ошибок, процесс renderer
   завершается. Механизм: `close_browser(1)` → `do_close` возвращает 1 →
   `detach_tab` убирает view → CEF уничтожает браузер → `on_before_close`.
   Если браузер не уничтожается после `remove_child_view`, это первое место
   для отладки.
4. Закрытие последней вкладки и крестик окна корректно завершают процесс
   (нет зависания и предупреждений CEF о незакрытых браузерах при shutdown).
5. F12 открывает DevTools в отдельном окне. Закрытие главного окна
   при открытых DevTools не должно ронять процесс.
6. `target=_blank` и Ctrl/Cmd+клик открывают вкладку справа от текущей.
7. macOS: приложение стартует из бандла, helper-процессы запускаются
   (песочница включена), работают Cmd+C/V в адресной строке и «Завершить»
   из Dock.
8. Несуществующий домен показывает страницу ошибки с исходным URL
   в адресной строке, а «Обновить» повторяет запрос.

## Дальнейшие шаги (по приоритету)

- `DownloadHandler`: загрузки с диалогом «Сохранить» и индикатором в панели.
- `PermissionHandler`: запросы камеры, микрофона, геолокации с UI в панели.
- Своя схема `rustium://` (SchemeHandlerFactory) вместо `data:`-URL для
  панели и служебных страниц.
- История и закладки (SQLite), подсказки в адресной строке.
- Восстановление сессии, перетаскивание вкладок, закрепление.
- Нативное меню macOS (Правка, Окно) вместо ручной обработки Cmd+C/V.
- Подпись и нотаризация `.app`, установщики (`.dmg`, AppImage/Flatpak).
